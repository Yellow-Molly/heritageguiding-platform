# Phase 03 — Validation & Review Report

**Status:** not-started
**Effort:** 1h
**Depends on:** Phase 02 (generated xlsx exists)

## Goal

Verify the generated xlsx is structurally correct, image URLs are reachable, and produce a human-readable review report that lists every default + every dropped field. Output is a markdown file the user reads before uploading to Bokun.

## Two Outputs

1. **Automated validation** — script `scripts/bokun-import/validate-output.mjs` (run after generator)
2. **Human review report** — markdown saved at `plans/260515-2013-bokun-import-spreadsheet-generation/review-report.md` (generated by the script)

## Automated Validation

Run as part of the generator (last step before "done") or standalone:

```bash
node scripts/bokun-import/validate-output.mjs docx/bokun-import-2026-05-15.xlsx
```

### Checks

| # | Check | Severity | Action on fail |
|---|---|---|---|
| 1 | All 13 sheets present with exact header strings matching template | error | exit 1 |
| 2 | `Products` row count == CMS published-tour count (10) | error | exit 1 |
| 3 | Every `Products.Product code` is unique | error | exit 1 |
| 4 | Every `Products.Product code` has matching rows in Pricing categories, Rates, Meeting points (1:1 each) | error | exit 1 |
| 5 | Every Photo row's `Product code` exists in Products | error | exit 1 |
| 6 | Every Photo URL is well-formed `https://` URL | error | exit 1 |
| 7 | Every Photo URL responds 200 OK (HEAD request; spot-check 1 per tour to avoid rate-limit) | warning | log + continue |
| 8 | Every Meeting point Title is non-empty | error | exit 1 |
| 9 | Coordinates either both filled or both empty (no partial) | warning | log row numbers |
| 10 | Duration hours + minutes > 0 for every product | error | exit 1 |
| 11 | All enum cols (Experience type, Booking type, etc.) match the locked defaults registry | warning | log if drift |
| 12 | Slug regex `/^[a-z0-9-]+$/` for every Product code | error | exit 1 |

## Post-Import Workflow

1. Upload `docx/bokun-import-2026-05-15.xlsx` in Bokun **test** environment → confirm all 10 import
2. Resolve any per-row import errors (likely 1–2 enum corrections; update `defaults.mjs` and re-generate)
3. Repeat against Bokun **production**
4. For each new Bokun Experience: copy ID → paste into Payload Tour `bokunExperienceId` field
5. Trigger "Sync to Bokun now" on each tour → confirms outbound PUT works
6. Manually add SV/DE translations + Highlights + prices in Bokun extranet (or schedule future plans)

## ID Write-Back Procedure (manual, ~10 min)

After Bokun assigns IDs, write them back:

```
For each tour:
  1. Bokun → Inventory → find Experience by Product code (= slug)
  2. Copy "Experience ID" (numeric, e.g. 1234567)
  3. Payload admin → Tours → open tour by slug → Bokun Experience ID field → paste → save
```

Future automation candidate: read Bokun's import-result xlsx (Bokun typically returns one with assigned IDs) and bulk-update Payload via a one-shot script that mirrors this generator's pattern.

## Acceptance Criteria

- [ ] All 12 automated checks pass (errors fixed before proceeding)
- [ ] `review-report.md` rendered with all sections populated
- [ ] Image spot-check shows ≥ 9/10 tours have reachable sample images
- [ ] User reviews report, confirms no surprises, then uploads to Bokun test
- [ ] Bokun test-environment import completes with ≤ 2 row errors (acceptable: enum drift)
- [ ] Each error from Bokun maps cleanly to a fix in `defaults.mjs` or `map-tour-to-bokun-rows.mjs`

## Open Questions to Resolve via Test Import

1. **Price amount column** — does Bokun bulk-import expect a price col we missed? If yes, add to Rates or Pricing categories sheet and regenerate.
2. **Enum string format** — `ACTIVITY_TOUR` vs `Activity tour`? Bokun's import-error message will reveal the expected format.
3. **Multi-value separator** — does Bokun parse `,` or `;` in Categories/Accessibility types?
4. **Highlights** — Bokun API has a dedicated `highlights[]` array. xlsx template has no Highlights col. Confirm by test: do imports lose highlights, or does Bokun extract them from Description?
5. **Image URL caching** — does Bokun fetch once at import (then cache) or re-fetch on every render? Affects whether CMS image URLs must stay stable indefinitely.
